# 실제 장비·파일럿 확인표 — 미실행

현재 소프트웨어 테스트는 실제 X40 출력이나 인간 참가자 검증을 대신하지 않는다. 이 파일의 항목은 자동으로 통과 처리하지 않는다.

## 장비 경로

1. Windows에서 기존 bHaptics Player 연결을 유지한다. 모델이 TactSuit X40인지 직접 확인하고 펌웨어/Player/SDK 버전을 기록한다. 새 페어링 도구를 설치하거나 연결을 초기화할 필요가 없다.
2. 프로젝트의 공식 SDK 앱을 Developer Window에서 연결·배포한다. 키는 SDK의 로컬 설정만 사용한다. Device Check에 표시되는 연결 장비 이름을 설정의 VerifiedDeviceName과 일치시킨다.
3. 공식 SDK 초기화 버튼으로 Player와 vest 연결을 확인한다. 기본 개발 모드는 실제 SDK를 초기화하지 않는다.
4. Calibration에서 실제 장비 테스트와 **미검증 raw 40채널 교정 시험 허용**을 명시적으로 선택한다. 이 허용은 실험 준비 완료를 뜻하지 않는다.
5. 낮고 편안한 개인 강도로 단일 채널을 시험한다. 40개 채널의 반응이 API/Player에서 실제로 전달되는지 확인한다. 40배열이 거부되거나 잘못 라우팅되면 중단한다. Pro32 배열로 대체해서 진행하지 않는다.
6. 각 모터 인덱스의 실제 몸통 수평 방위각과 위치 보정값을 입력·저장하고 개별 확인을 표시한다. 같은 방위각의 서로 다른 수직 행을 명시할 수 있다. 전면/후면 좌우 반전을 별도 확인한다.
7. 0/90/180/270°와 중간 각도·360° 경계의 보간을 시험한다. 가상 40등분 맵을 실측 맵으로 표시하지 않는다.
8. 거리 6/12/24/36m 및 중간값에서 강도 순서를 확인한다. gain/clamp/정수 양자화로 여러 거리가 같은 배열이 되는지 확인한다. L/H는 참가자별로 확정한다.
9. 3개 위협을 max 합성한 **한 요청**의 실제 동시성을 계측/관찰하고 기록한다. 같은 모터에 겹친 약한 신호 소실도 확인한다. 요청 배열의 동일성은 피부 자극 동일성의 증거가 아니다.
10. 지정 시간 출력 종료, 긴급 중지, 창 포커스 이탈, 장비 분리, SDK 거부를 시험한다. 출력 실패 시행이 정상 자료에서 제외되고 원본 요청과 로그가 일치하는지 확인한다.
11. 검증 근거·실측 매핑 버전·SDK 버전을 저장한 뒤에만 물리 매핑/40채널 처리/동시성/강도/지속시간/정렬 확인을 표시한다. SDK 요청 ID는 전달 ACK가 아니다.

## 파일럿 (초기 계획 4~6명, 실제 자료만)

- 사전에 방향/거리 정답률 하한과 조건 쌍별 동일 배열 비율 상한, 피로·불편함 및 중단/제외 기준을 기록한다.
- 단일 방향, 거리 세 범주, 위치 감도, 펄스 길이, 동시 자극, 원형 응답, 전체 소요시간을 확인한다.
- Stimulus Validation은 실제 고정할 프로파일·L/H·duration에서 재실행한다. 최대 조건 쌍 동일 비율은 MAIN 게이트가 다시 계산한다.
- 방향 허용오차는 실제 파일럿 자료로 정한다. 임시 개발용 15°를 본 실험 확정값으로 간주하지 않는다.
- 근거 파일을 준비하고 해시를 저장한다. 인지 성능·불편함 기준 충족은 연구자의 실제 자료 검토와 확인이 필요하다. 소프트웨어는 참여자 결과를 생성하거나 대체하지 않는다.
- 표본 수·최소 관심 효과·통계모형·동률 기준·훈련/재훈련·제외 규칙과 B 첫 대응 기준을 확정하고 설정을 잠근다.
- 본 실험 전 참가자 몸통 정면과 카메라 정면을 맞춘다. B 참가자는 A와 독립적으로 모집한다.

## 아직 남은 결정

실측 X40 인덱스 매핑, 출력 동시성/지연, 개인 강도, 감도 보정, 최종 duration, 방향 허용오차, B 제한시간·정면 사격 구역, 최소 관심 효과, 최종 표본 수와 근거, A 후보 동률 처리, 훈련 기준·횟수·종료, 기술 실패·제외, 주 분석 모형. 빈칸을 임의의 연구 확정값으로 채우지 않는다.

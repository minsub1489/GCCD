# UI / Player 연결 / FPS 미션 변경 검증

- 기본 연결을 공식 구형 PlayerRequest 로컬 WebSocket 경로로 추가. SDK 계정·개발자 앱 키 없이 현재 Player에서 조끼 1대 연결을 확인함.
- 실제 Player 활성 요청 목록에 20%, 200ms 단일 모터 테스트 키가 나타남. 사용자는 착용하지 않아 체감 여부를 확인하지 못함. 물리 매핑·동시성 검증 완료로 기록하지 않음.
- 앱 키를 비운 별도 빌드에서 시작 화면의 자동 연결 성공 표시를 시각적으로 확인함. 새 빌드는 Player 초기화 대기 중에도 화면 갱신이 가능하도록 background 실행을 켜며, 실험/미션의 포커스 이탈 일시정지는 유지함.
- 첫 화면은 연결 / 진동 확인 / FPS 미션·화면 연습으로 재구성. 연구 교정과 A/B 운영은 고급 화면으로 유지.
- 비활성 SDK 초기화 프리팹이 있어도 중복 추가하지 않는 회귀 검사 통과.
- Kenney CC0 3종 FBX/텍스처 라이선스 파일 포함. 미션 생성 시 45개 MeshRenderer 확인. 실제 카메라 렌더링으로 배경/건물/컨테이너/드럼통/총기를 확인함.
- Unity Play Mode에서 보급품 3개 수집, Raycast 표적 5개 명중, 가상 돌발 자극 요청, 월드·CharacterController 정리와 메뉴 복귀 통과.
- 독립 C# 61개, Python 분석 5개 통과. A 108시행 통합 검증 통과.
- Windows x64 빌드 190,668,942 bytes / macOS 빌드 359,143,083 bytes 성공. Windows 실제 실행은 미검증.
- OS 자동 입력 도구의 Unity IMGUI 좌표 클릭으로는 미션 진입을 확인하지 못했으며, Play Mode의 동일 동작 메서드와 실제 카메라 렌더링으로 별도 검증함. 네이티브 키보드/마우스로 전체 미션을 완료했다고 주장하지 않음.
- 소스 편집 전부터 존재한 ProjectSettings.asset 변경과 PackageManagerSettings.asset 미추적 파일은 보존함. 현재 사용자의 씬을 재생성하지 않고 별도 로컬 검증 사본에서 빌드함.

연구용 본 실험은 실측 프로필과 해당 local-player-v1 출력 경로 검증을 필요로 하며 자동 해제하지 않는다. 미션은 MISSION_DEMO 전용 기록으로 본 실험 자료에 합치지 않는다.

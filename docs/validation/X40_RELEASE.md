# X40 매핑·방향 검사·지도 좌표 수정 검증

전송은 원래 앞20/뒤20이었지만 미션 렌더링에 가상 9도 원형 프로필을 쓰던 문제를 수정했다. 공식 legacy VisualFeedback/Visualizer의 4열×5행 인덱스와 model.h의 201/202 패널 ID를 근거로 기본 X40 템플릿을 구성했다. 실제 몸통 방위각은 8열 모델이며 착용자 실측값으로 가장하지 않는다. 공식 SDK2 PlayMotors 쓰기 대체 경로를 제거해 X40 출력은 Player 20+20만 사용한다.

방향 모달에서 네 방향을 0.2초씩 요청하고 사용자가 실제로 느낀 경우만 확인 수를 올린다. 앞/뒤 패널별 좌우 반전과 앞뒤 교환을 로컬 설정에 저장한다. 미션과 검사에 동일한 프로필을 사용한다. Calibration 및 본 측정의 PhysicalLayoutVerified/PlacementConfirmed를 자동으로 채우지 않는다.

RED 체크포인트 d10877e: X40Layout 미구현 상태의 8개 신규 검사 컴파일 실패. GREEN: C# 91 passed / 0 failed. 5행×4열×2면, 네 방향 채널, 독립 반전/교환, 19/20/39 채널 보존, 32배열 거부, 거리 감쇠와 359/1도 경계를 확인했다. 반올림 경계에서 부동소수 잡음으로 대칭 출력이 1단계 달라지던 현상도 정리해 AwayFromZero 양자화 의도를 유지했다.

RED 체크포인트 24481e2: 실제 PointerDownEvent 클릭에서 기대 좌표(-18,-5.5)가 (-17.769184,-5.730817)로 바뀌는 실패를 관찰했다. contentRect의 테두리 오프셋을 반영한 뒤 같은 검사와 UI 0.8 배율 검사가 통과했다. 기록된 응답과 결과 지도 마커 일치, 실제/응답 좌표 뒤바뀜 없음, 완료 전 정답 숨김을 검사했다. 기존 저장 응답을 보정한 것처럼 바꾸지 않는다.

Unity DTS_RESULT_FLOW_PASS / DTS_MISSION_PROBE_PASS, 방향 모달 열기·닫기와 4방향 버튼, 결과 지도 및 CSV 재저장 검사를 수행했다. UI 렌더를 직접 검토했다. Python 분석기 5개 및 Windows/macOS Release 빌드도 통과했다. 기존 Unity Editor Search 내부 예외가 남은 실행에서도 게임 검사와 빌드는 통과했다. 코드 커버리지는 측정하지 않았다.

실제 X40 착용자의 네 방향 체감, 40개 모터 개별 위치, 물리 동시성 및 Windows 실기기 실행은 소프트웨어 검사로 확인하지 않았다. 사용자가 조끼를 입고 방향 모달에서 확인할 수 있도록 제공한다. 테스트가 방향 확인 버튼을 대신 눌러 실제 교정 완료로 기록하지 않는다.

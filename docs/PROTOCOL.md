# 프로토타입 실험 사양

## 비교 조건

| 조건 | 음향 | 진동 |
|---|---|---|
| AudioOnly | 기본 3D 음향 | 없음 |
| AlertOnly | 동일 | 4채널 모두 0.22, 방향·거리 무관 |
| Direction | 동일 | 해당 전후·높이 채널, 기준 강도 0.55 |
| DirectionAndDistance | 동일 | 위치 채널 + 가까움 0.85 / 중간 0.55 / 멂 0.30 |

펄스는 350ms입니다. 같은 높이의 두 채널은 각각 `pairedGain=0.70`을 곱합니다. **이 수치는 체감 강도 등가성을 검증한 값이 아닙니다.** AlertOnly와 방향 신호의 총 체감 강도를 본 실험 전에 별도로 보정해야 합니다.

거리 단계는 음량이 아니라 음원과 관찰자의 직선거리로 계산합니다: 8m 미만 / 8m 이상 12m 미만 / 12m 이상. 수평 반경은 6, 10, 14m이고 높이 오프셋은 -3.5, 0, +3.5m입니다. 관찰자 눈높이는 세계 y=4.5m입니다. 높이 분류 경계는 ±1m입니다.

신호 시작 때의 수평 전방벡터와 음원 방향의 내적으로 전후방을 확정합니다. 재청취 시에도 같은 최초 분류를 유지하며, 음향 방향은 실제 카메라 회전을 따라 바뀝니다.

## 시행 진행

1. 카메라를 정면으로 초기화하고 1.3초 준비합니다. 이 단계에서는 시점을 돌리지 않습니다.
2. 신호가 시작되고 자유롭게 시점을 회전할 수 있습니다.
3. 20초 안에 조준점으로 드론을 선택합니다. 최초 선택만 저장합니다.
4. 거리 버튼을 응답합니다. 거리 응답에는 별도 시간제한이 없습니다.
5. 연습에서는 정답·실패를 표시하고, 본 실험에서는 기록 완료만 표시합니다.
6. 사용자가 계속 버튼을 눌러 진행합니다. 조건 사이에도 쉬어갈 수 있습니다.

이 버전은 **위치 판단용 고정 관측 데모**이며 이동·전투 게임이 아닙니다. 일부 전방 드론은 시작 시야에 들어오지만 모든 드론이 동일하게 표시되며 발음 중 시각적 정답 단서는 없습니다. 엄격한 '모든 자극이 화면 밖' 설계는 아직 아닙니다.

## 음향과 차폐의 한계

Unity AudioSource의 3D 패닝, 선형 거리 감쇠(1–23m)를 사용합니다. HRTF 공간화 플러그인은 지정하지 않았습니다. 높이·전후방 음향의 타당성을 주장할 수 없습니다.

차폐 조건은 전체 음원에 같은 볼륨 비율(0.28 대 0.75)과 저역통과 필터(1,300Hz 대 22,000Hz)를 적용한 **실험 자극 스위치**입니다. 보이는 패널은 조건을 나타내는 장식이며, 실제 벽 레이캐스트·회절·반사·투과 시뮬레이션이 아닙니다. 장식 패널이 정답 드론만 가리키지 않도록 전 방향에 동일하게 배치합니다. Steam Audio 도입 시 이 처리를 교체해야 합니다.

## 실제 장치 연결

기본 `HapticOutput.udpEnabled=false`입니다. Editor의 `Research session → Haptic Output`에서 활성화할 수 있습니다. UDP는 **127.0.0.1:9050**으로만 전송합니다. 별도의 로컬 브리지가 수신하여 실제 장치를 제어해야 합니다.

```json
{"version":1,"durationMs":350,"channels":[0.55,0,0,0]}
```

순서는 앞 위, 앞 아래, 뒤 위, 뒤 아래입니다. 중지 패킷은 durationMs=0, 모든 채널=0입니다. UDP는 전달·출력을 보장하지 않으며 화면도 `hardware delivery unverified`로 표시합니다. 브리지는 durationMs와 독립 watchdog으로 출력을 자동 종료해야 합니다. 실제 장치 ACK, 펌웨어, 지연 계측은 구현되어 있지 않습니다.

본 실험 UI는 모터 미리보기를 숨깁니다. 장치 미연결 상태에서는 네 조건의 촉각 차이를 느낄 수 없습니다. **소프트웨어 연결 검사용으로만 사용하세요.**

## CSV 해석

- face: 0=앞, 1=뒤; height: -1=아래, 0=같음, 1=위; distance: 0=가까움, 1=중간, 2=멂.
- 무응답은 response_face=-1, response_height=-9, response_distance=-1.
- `selection_ms`: 음원 재생 요청부터 최초 드론 선택까지의 소프트웨어 시간. 실제 음향/진동 발생 시점 계측값이 아님.
- `total_response_ms`: 거리 응답까지 포함. timeout 또는 중단이면 종료 시각까지.
- `target_correct`: 실제 발음 드론 일치. face_correct/height_correct는 선택 드론의 개별 공간 분류 일치.
- `distance_correct`: 명시적 거리 응답 일치. 모든 후보는 같은 반경이므로 드론 선택으로 거리 응답을 대체하지 않습니다.
- `replays`: 최초 재생 이후 추가 재청취 수.
- `outcome`: answered / timeout / aborted / focus_lost. 중단 시행을 정답률 분모에 무조건 포함하지 말고 별도로 보고하세요.
- `practice`, `visual_motor_preview`, `udp_enabled_at_onset`, `audio_backend`를 확인하여 데이터 출처와 모드를 구분하세요. UDP 활성화는 물리 출력 검증을 뜻하지 않습니다.

자동 점검은 매우 빠르게 호출되므로 시간값이 0에 가까울 수 있습니다. 합성 CSV를 참여자 반응 시간으로 쓰지 마세요.

## 연구 전에 남은 작업

Steam Audio/HRTF 통합, 기기별 전후·높이 음향 확인, 모터 및 동시 진동 체감 강도 보정, 실출력 지연 측정, 불편함 설문, 세션 간 참가자 익명코드 관리, 연구자가 결정한 제외 기준과 counterbalancing 배정이 필요합니다. 화면 시뮬레이션의 효과와 착용형 촉각의 효과를 구분해야 합니다.

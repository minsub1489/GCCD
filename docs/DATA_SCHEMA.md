# 데이터·측정 계약

## 파이프라인

활성·화면 밖·같은 발포 이벤트인 모든 위협을 거리 오름차순, ID ordinal 순으로 정렬해 먼저 최대 3개를 선택한다. 양수 억제각은 **유지된** 위협과 원형 오차가 `<= theta`이면 제거한다. 첫 충돌 유지 위협(가까운 순)을 부모로 기록한다. 억제 후 4·5위로 보충하지 않는다. 0°는 같은 방향도 모두 유지한다.

0° 정면, 90° 오른쪽, 180° 뒤, 270° 왼쪽이다. 위치는 Unity world 좌표(m), 방위는 이벤트 시점 수평 카메라 yaw를 기준으로 한다. 실제 직선거리를 사용한다. B는 이벤트 이후 위치·정책·모터 프레임을 다시 계산하지 않는다.

## 자극 생성

18계열은 **최소 쌍별 원형 간격**의 6구간 내부값 × 3반복이다. 세 번째 방향은 쌍의 반대편 중앙에 둔다. 실제 화면 밖 여유를 확보할 수 있는 회전만 채택한다. FOV에서 가능한 배치가 없으면 실패하며 간격 조건을 바꾸지 않는다. xorshift32와 seed로 재현한다. 같은 계열의 거리 multiset은 여섯 조건에서 동일하고, 거리 순위의 방향 배정·반전·회전과 블록 내 순서를 바꾼다. 한 거리 범주에 2~3개가 포함되는 배치도 존재한다. 조건별 방향 분포의 최종 허용 기준은 파일럿에서 진단해야 한다.

## 모터 요청

프로파일의 고유 방위각 열 사이를 원형 선형 보간한다. 같은 각도의 행들은 같은 가중치를 받는다. 위치 gain을 적용하고 SDK 범위에 clamp한 후 모터별 max, 0..100 정수 AwayFromZero 양자화를 적용한다. 각 원본 위협의 개별 배열과 최종 제출 배열을 따로 기록한다. 가상 9° 간격 40채널 프로파일은 디버깅용이고 X40 실제 배치가 아니다.

`SIMULATED_NO_PHYSICAL_OUTPUT`은 가상 출력, `SDK_REQUEST_ACCEPTED_PHYSICAL_UNCONFIRMED`는 SDK가 비음수 요청 ID를 반환한 수준이다. 후자는 피부 진동 성공이나 독립적인 장치 ACK가 아니다. 요청 시작/반환의 단조 시각과 UTC를 저장하며, 실제 하드웨어 onset을 측정한 값으로 해석하지 않는다. 자극 종료 대기는 SDK 반환 후 지정 지속시간 이상이며 실제 기다린 시간을 따로 기록한다.

## 채점

A 정상 시행은 원래 3개를 분모로 한다. 0~3개 응답의 가능한 모든 일대일 매칭을 열거하여 공동 정답 수 최대 → 전체 각도 오차 최소 → 사전식 인덱스 순으로 선택한다. 응답은 최대 한 위협에만 매칭한다. 억제된 위협도 정답 집합에 남는다.

- joint_accuracy: 방향 오차가 고정 허용오차 이내이고 거리 범주가 같은 매칭 수 / 3.
- direction_accuracy, distance_accuracy: 각각의 기준만으로 최대가 되는 별도 일대일 매칭 수 / 3.
- direction_error: 공동 정답 최적 매칭의 모든 제출 응답에 대한 평균 원형 오차. 무응답 결측.
- response_precision: 공동 정답 수 / 응답 수. 무응답 결측.
- false_response_rate: 공동 오답 응답 수 / 응답 수. 무응답이면 0이며 no_response_rate=1.
- ambiguous_matching: 공동 정답 최대인 매칭들에서 정답 response↔threat edge 집합이 여러 개인 경우.
- distance_confusion: 공동 최적 매칭에서의 실제 범주×응답 범주. 독립 distance_accuracy 최적 매칭의 행렬이 아니다.
- matched_threat_id: 분석 알고리즘의 대응 ID이다. 참가자가 진동으로 적 ID를 알아냈다는 의미가 아니다.
- matched_distance_sorted_index: 거리순 원래 선택 집합의 0-based 인덱스. 위협 CSV 행 번호나 응답 입력 순서가 아니다.

범주는 Near=[6,12), Middle=[12,24), Far=[24,36]. 강도 함수의 거리 입력은 [6,36]으로 제한한다. 원본 위협 거리는 범위 밖이면 연구 채점 오류로 처리한다.

훈련의 처음 3개 단일 자극은 학습 피드백용이며 단일 자극 기준 정답을 기록한다. 이후 세 위협 훈련은 /3 채점을 사용한다. 모든 훈련은 별도 TRAINING 자료로 저장하며 A 본 시행과 합치지 않는다.

## B 첫 대응

Raycast가 FRONT 과제 표적을 맞히거나, 미명중 사격 방향이 **고정된 세계 정면 과제 구역**의 사전 확정 반각 안이면 정면 과제 사격으로 분류한다. 그 밖의 첫 사격은 외부 대응이다. Raycast 적 ID가 최근접이고 실제 명중했으며 단조 시간 기준 `< deadline`일 때만 성공한다. 미명중은 빈 target ID로 기록하고 이후 명중으로 첫 실패를 덮어쓰지 않는다. 정확히 deadline인 경우 시간 초과이다. 정면 구역 반각·제한시간·분류법은 B 전에 고정해야 한다.

B는 첫 대응 후에도 제한시간까지 플레이하고 추가 적중·카메라 회전 경로·정면 과제 사격을 기록한다. additional_threats_hit는 해당 이벤트에서 한 번 이상 맞힌 외부 적의 고유 수다. 실패/무대응도 성공률 분모에 남는다. 프레임 드롭 시 시간 초과 판정을 새 입력보다 먼저 처리한다.

## 저장·복구

UTF-8, invariant 숫자, UTC ISO8601과 Unity 단조 시간을 구분한다. 원본 JSON 완료 파일은 `{"sha256":"...","record":{...}}`이며 hash는 envelope 안 record의 정확한 원본 문자 payload를 UTF-8로 인코딩한 값이다. checksum은 우발적 손상 감지용이며 악의적인 수정에 대한 전자서명이 아니다.

시행 전에 started snapshot과 요청 전 이벤트를 flush하고, 출력 결과를 flush한다. 완료 JSON은 임시 파일→원자적 이동/교체 후 CSV를 재생성한다. 여러 CSV 사이의 동시 원자성을 주장하지 않는다. 종료 중 일부 CSV가 오래된 경우 완료 저널에서 복구한다. 세션 파일 잠금으로 동시 기록을 막고 동일 trial ID를 거부한다. 미완료 snapshot은 기술 실패로 확정하며 새 응답을 생성하지 않는다.

정상 출력이 없거나 기술 실패인 시행은 정답률을 정상 시행으로 보고하지 않는다. technical_failure가 있는 경우 남은 원본 점수값이 있더라도 분석에서 제외하고 기술 실패율에 포함한다. 시험 자료는 mode와 별도 폴더로 식별한다.

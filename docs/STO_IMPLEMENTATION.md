# STO 논문과 X40 실험 구현의 범위

참조: Dajin Lee, Seungmoon Choi, **Spatial Tactile Optimizer: Toward Perceptual Optimization for Multi-Point Vibrotactile Cues on the Torso**, CHI EA 2026, [DOI 10.1145/3772363.3798642](https://dl.acm.org/doi/10.1145/3772363.3798642). 사용자가 연 ACM 원문에서 알고리즘과 실험 장치 설명을 확인했습니다.

STO는 복수 촉각 신호가 서로 합쳐져 느껴지는 문제를 다룹니다. 논문 자체가 청각 마스킹 상황의 위험 이벤트를 분류하거나 선택하는 알고리즘은 아닙니다. 이 프로젝트에서는 `ThreatSelectionPolicy`가 게임 이벤트의 중요도·예상 마스킹을 선택하고, `StoTorsoOptimizer`가 선택된 복수 촉각 신호를 최적화합니다.

## 논문에서 반영한 수식

- 지각 분포와 물리 출력: `p̃ = P s`, `v = A s`.
- 각 목표 방향의 30° 이내 후보 지점 중 1개를 이산 피크로 선택합니다.
- 선택된 지점은 `P s`의 국소 최대가 되도록 이웃 지점과 비교합니다.
- 목표 지각 강도는 Stevens 지수 `γ = 0.8`을 이용해 `Iphysical = Iperceptual^(1/γ)`로 변환합니다.
- 목적식은 평균 방향 오차, 평균 강도 오차, 가까운 피크 쌍의 최소 간격, 평균 액추에이터 에너지의 가중합입니다. 기본 가중치는 각각 `0.5, 0.5, -10, 0.05`입니다. 각도 비교는 원형 최단거리입니다.

프로젝트 코드는 이산 피크 조합을 열거하고, 고정된 조합의 연속 강도 문제를 `StoLinearProgram`의 2단계 simplex로 풉니다. 별도의 상용 솔버가 필요하지 않습니다. 제한 시간 안에 얻은 실행 가능한 해를 사용하며 해를 얻지 못하면 직접 3D 매핑으로 돌아갑니다. 매번 전체 최적해를 보장하지 않습니다.

## 동일 재현이 아닌 부분

논문은 수평 몸통에 배치한 8개 LRA, 서로 다른 주파수(80/200 Hz) 및 지각 실험에서 구한 primitive 분포를 사용하고 Gurobi MILP로 계산합니다. 논문의 실험 정확도와 계산 시간은 이 X40 구현의 검증 결과가 아닙니다.

현재 X40 실험 구현은 다음과 같이 다릅니다.

1. X40의 40개 모터에 대한 기존 연속 3D 공간 매핑을 `A`로 사용합니다. SDK의 정수 모터 강도 API로 주파수를 지정할 수 없어 논문의 주파수 primitive를 동일하게 만들지 않습니다.
2. `P`는 16개 수평 방향 primitive의 원형 Gaussian을 60개(6° 간격) 위치에서 샘플링하는 임시 해석 모델입니다. 기본 폭 18° 및 ClosePairDegrees=90°는 이 프로젝트의 미보정 설정입니다. 원문의 측정 행렬을 확보한 것으로 취급하지 않습니다.
3. 사용자가 측정한 16개 primitive의 평균 오프셋과 폭을 `PrimitiveMeanOffsets / PrimitiveSpreads`에 넣을 수 있습니다. 이것만으로 논문의 전체 원시 데이터·주파수·강도별 모델을 동일하게 재현한 것은 아닙니다.
4. 현재 복수 최적화는 2–3개 신호를 지원합니다. 1개 또는 4개 신호, 수직 극점(고도 절댓값 > 80°), 오류·해 없음에서는 기존 3D 매핑을 사용합니다.
5. 논문의 수평 지각 최적화에 X40의 고도별 출력 행을 연결하는 확장입니다. 수직 방향의 다중 피크 지각은 이 `P` 모델로 검증되지 않았습니다.
6. 전체 출력 합은 기본 최대 강도 0.5 이내로 제한하고, 이후 평활화와 0–100 정수 양자화 및 유한 길이 SDK 펄스를 적용합니다. 이 후처리와 장치 지연도 원문과 다릅니다.

`X40CalibrationVerified`는 기본 false입니다. 실장치 측정과 참가자 지각 검증이 완료된 뒤 연구자가 표시해야 합니다. 미검증 상태에서 STO를 켠 본 진동 블록은 시작되지 않고, 연습 미리보기만 가능합니다. UI의 `Experimental STO adaptation`과 로그의 상태 문자열은 이 한계를 표시합니다. 소스 코드에는 논문 측정표나 논문 제공 코드가 아닌 독립적으로 작성한 알고리즘이 들어 있습니다.

## 점검

검사는 LP의 알려진 최적해·음수 우변·실행 불가능/무한 문제, STO의 서로 떨어진 두 피크에 대한 실행 가능한 해, 후보 각도 제한·출력 예산·원형 경계·극점 대체를 확인합니다. 이 계산 검사는 사람에게 신호가 더 잘 구분되는지를 검증하지 않습니다. 최적화 상태, 계산 시간, 렌더링 방향, 실제 40개 정수 출력은 `haptic_decision` 로그에 기록됩니다.

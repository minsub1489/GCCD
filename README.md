# 현재 실행 방법

**[Windows 실행 파일 다운로드](https://github.com/minsub1489/GCCD/releases/tag/v0.9.7-suppression-sectors)** · **[빠른 시작 안내](docs/QUICK_START.md)** 시작 화면에서 Player의 조끼를 자동으로 찾습니다. **진동 · 방향/거리 확인**에서 X40의 네 방향과 거리별 세기(36m 약함 / 21m 중간 / 6m 강함)를 시작 전에 비교합니다. [X40 매핑 안내](docs/X40_MAPPING.md). 로그인/App ID/API Key 없이 Player 로컬 연결을 사용합니다. **작전 시작**으로 공업지대 보급품 회수 미션을 플레이합니다.

실사 기반 PBR 벽돌·아스팔트, 스캔한 드럼통·방호벽·군용 상자, HDR 하늘과 AKM 모델을 포함합니다. 실내 작업실·창고 16개와 복도를 연결했습니다. 우클릭 조준, 좌클릭 연사, Space 점프, C 앉기, Tab 미니맵을 지원합니다. 위협 진동 요청 때 게임을 멈추고, 실제 개수를 숨긴 위치 응답 지도에서 표시를 완료하면 재개합니다. 실행 중 에셋 다운로드가 필요하지 않습니다. 연구 실험은 메인의 **실험 시작**에서 바로 진행합니다.

아래 SDK 앱 연결 설명은 기존 SDK2 경로에 대한 안내입니다. 새 기본 Player 직접 연결에는 필요하지 않습니다. [무료 에셋 출처](docs/FREE_ASSETS.md).

# GCCD — FPS 다중 위협 햅틱의 거리 우선 방향 억제각 비교

정면을 포함한 360°에 같은 수의 위협을 무작위로 배치하고 **0 / 15 / 30 / 45 / 60 / 90°**를 비교합니다. 설정한 수의 무작위 배치를 모든 조건에서 공유하며, 조건마다 시행 순서를 섞습니다. 가장 가까운 위협부터 유지 여부를 정하고, 이미 유지된 위협과의 원형 각도 차가 억제각의 절반 이내면 억제합니다. 0°에서는 전부 유지합니다.

메인에서 참가자 ID를 입력하고 **실험 시작**을 누릅니다. **응답 연습**에서는 지도 사용법을 연습합니다. 실험은 6블록이며 조건당 시행 수는 설정값입니다. 화면 연습 기본은 조건당 18시행입니다. 각 시행은 2~4초 준비 → 자극 → 12초 응답 → 혼란도 기록으로 진행합니다. 지도에 방향을 표시하고 거리 범주를 고릅니다. 빈 응답도 제출할 수 있습니다.

Unity에서 실행하려면 Unity 6000.3.24f1로 `GCCD_Project`를 열고 `Assets/Scenes/DistancePriorityStudy.unity`에서 Play를 누릅니다. 로비에서 F9를 누르면 장비 확인·교정·자극 검증·데이터 검토를 엽니다. 시행 중 ESC는 중지·일시정지, F9는 운영 화면을 엽니다.

## X40 연결·교정

기존 bHaptics Player의 페어링과 연결 설정을 유지합니다. [장비 확인 절차](docs/HARDWARE_ACCEPTANCE.md)를 따르세요.

- 공식 SDK2는 선택 기능이며 저장소에 포함되지 않습니다. 기본 Player 직접 연결은 SDK 설치 없이 동작하도록 구성합니다. SDK2 경로를 사용하려면 해당 PC에 정식 **bHaptics Haptic Plugin (SDK2)**를 설치하세요.
- **GCCD → bHaptics SDK2 → Check Official SDK and Add Prefab / Enable Compile-Time Adapter**로 공식 초기화 프리팹과 어댑터를 확인합니다. 기본 씬의 초기화 프리팹은 비활성 상태입니다. 개발 모드는 SDK를 초기화하거나 진동을 출력하지 않습니다.
- 공식 Developer Window에서 기존 앱을 연결·배포한 뒤 **장비 확인 → 공식 SDK 초기화 및 연결 확인**을 누릅니다. 키는 연구 설정·로그·Git에 저장하지 않습니다.
- 공식 [PlayMotors 문서](https://docs.bhaptics.com/sdk/unity/references/library)는 Vest의 32모터 배열을 명시합니다. 로컬 SDK 구현은 배열 길이를 네이티브 API에 전달하지만 이것만으로 X40 40채널 호환성을 증명하지 않습니다. 32모터 맵을 복사하거나 `PlaySingleMotor`를 X40 인덱스 테스트에 사용하지 않습니다.
- 교정 화면의 실제 장비 시험은 연구자가 명시적으로 허용해야 합니다. 단일 모터를 확인하고 40개 인덱스의 실제 방위각·보정값을 저장합니다. API의 40채널 처리와 물리 동시성을 별도로 확인합니다.
- 위협별 출력을 순차 호출하지 않습니다. 40채널 **최댓값 합성 배열 한 개**를 제출하며, 새 위협마다 이전 요청을 취소하지 않습니다. 정수 강도는 0~100, 양자화는 AwayFromZero입니다.

## 본 실험 설정

설정은 `Application.persistentDataPath/DtsSettings/experiment_config.json`에 저장합니다. 화면에 전체 경로가 표시됩니다. F9에서 **설정 저장**으로 파일을 만든 뒤 직접 편집할 수 있습니다. `TotalThreatCount`는 0(미확정) 또는 2 이상입니다. 미확정 상태의 화면 연습은 임시 6개로 실행합니다. 실제 측정 전에 위협 수와 파일럿에서 검토한 `TrialsPerCondition`을 지정하고 `LobbyMode`를 `PILOT` 또는 `MAIN`으로 설정하세요. 기본은 `DEVELOPMENT`이며 화면 연습으로 표시됩니다. 파일을 수정한 뒤 **설정 불러오기**를 누르거나 앱을 다시 실행합니다. 연구 설정에는 SDK 자격증명 필드를 넣지 않습니다.

방향 허용오차, L/H, 위치 보정, 지속시간, 표본 수 근거, 최소 관심 효과, 동률 처리, 훈련 기준·재훈련 횟수·종료 규칙, 실패·제외 규칙과 주 분석 모형은 파일럿/사전등록 후 확정해야 합니다. 개발 모드의 미설정 방향 허용오차는 **임시 15°**로 동작하며 실제 연구의 확정값이 아닙니다.

MAIN은 장비·교정 확인, 사전 파일럿 기준과 실제 근거 파일의 SHA-256, 설정 잠금, 같은 참가자·같은 설정의 훈련 통과가 필요합니다. 파일럿의 최대 조건 쌍 동일 배열 비율을 넘는 자극은 자동 차단합니다. 파일럿 방향·거리 인지 성능 충족 여부는 연구자가 실제 자료로 판정하며 자동으로 만들어 주지 않습니다. 설정 변경 후에는 다시 잠그고 훈련합니다.

## 데이터와 재개

기본 경로: `Application.persistentDataPath/ExperimentData/<자료구분>/A360/<익명 ID>/<세션 ID>/`.
개발·파일럿·본 실험·훈련·교정·자극 검증 자료를 분리합니다.

- `session_metadata.json` / `.sha256`: 설정 스냅샷, Unity/SDK/매핑 버전, 시드, 실제 블록 순서와 설정 해시.
- `journal/*.started.json`: 출력 전에 내구성 있게 기록하는 원본 위협·정책·요청 배열.
- `journal/*.committed.json`: 정확한 JSON payload의 SHA-256을 포함하는 원자적 완료 기록.
- `runtime_events.csv`: 출력 요청 전/후, 응답 시작, 출력 중지 기록.
- `trials.csv`, `threats.csv`, `haptic_outputs.csv`, `responses.csv`: 분석용 파생 테이블.
- `distance_confusion.csv`, `data_validation.csv`: 매칭 진단과 무결성 오류.

각 완료 기록이 원본이며 CSV는 재생성할 수 있습니다. 비정상 종료 후 **세션 재개**에 기존 폴더를 입력하면 완료 시행을 재출력하지 않습니다. 미완료 시행은 기술 실패로 확정하고 다음 시행부터 계속합니다. 자동 재시행이나 참가자 응답 보정은 하지 않습니다. 데이터 검토에서 체크섬을 확인하고 CSV를 재생성할 수 있습니다. 이전 방식의 A/B 세션은 CSV로 검토할 수 있으며 재개는 해당 버전에서 진행합니다.

```sh
./scripts/run-core-tests.sh
python3 scripts/analyze_session.py '/실제/세션/폴더'
```

분석기는 한 세션의 조건별 기술통계를 출력합니다. 개발 세션에는 자극·배치 통계만 표시합니다. 정답률의 분모는 억제 여부와 관계없이 시행의 전체 위협 수입니다.

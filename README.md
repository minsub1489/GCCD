# 현재 실행 방법

**[빠른 시작 안내](docs/QUICK_START.md)** 를 먼저 보세요. 시작 화면에서 Player의 조끼를 자동으로 찾습니다. 로그인/App ID/API Key 없이 Player 로컬 연결을 사용합니다. **작전 시작**으로 공업지대 보급품 회수 미션을 플레이합니다.

실사 기반 PBR 벽돌·아스팔트, 스캔한 드럼통·방호벽·군용 상자, HDR 하늘과 AKM 모델을 포함합니다. 실내 작업실·창고 16개와 복도를 연결했습니다. 우클릭 조준, 좌클릭 연사, Space 점프, C 앉기, Tab 미니맵을 지원합니다. 위협 진동 요청 때 게임을 멈추고, 실제 개수를 숨긴 위치 응답 지도에서 표시를 완료하면 재개합니다. 실행 중 에셋 다운로드가 필요하지 않습니다. 기존 실험 A/B는 **연구자 설정**에서 운영합니다.

아래 SDK 앱 연결 설명은 기존 SDK2 경로에 대한 안내입니다. 새 기본 Player 직접 연결에는 필요하지 않습니다. [무료 에셋 출처](docs/FREE_ASSETS.md).

# GCCD — FPS 다중 위협 햅틱의 거리 우선 방향 억제각 비교

거리 우선 상위 3개 위협에 **0 / 15 / 30 / 45 / 60 / 90°** 방향 억제를 적용하는 Unity 연구 플랫폼입니다. 기존 2×4 위협 수·강도 연구 실행 코드는 제거했으며 시작 커밋 `e855d67`에서 복구할 수 있습니다. 이전 참가자 자료나 외부 GCCD 사본은 수정하지 않았습니다.

**소프트웨어 시뮬레이션과 장비 검증을 구분합니다.** 가상 모터 맵은 X40 인덱스 배치가 아닙니다. 본 실험에는 실기기 검증, 실제 파일럿, 설정 확정과 참가자 훈련 통과가 필요합니다. 현재 파일럿 결과나 연구 효과를 생성하지 않았습니다.

## 실행

1. **Unity 6000.3.24f1**에서 `GCCD_Project`를 엽니다. 기존 엔진 버전을 유지합니다.
2. `Assets/Scenes/DistancePriorityStudy.unity`를 열고 Play를 누릅니다. 재생성 메뉴는 **GCCD → Distance Priority → Generate Experiment Scene**입니다.
3. 우선 **개발** 모드를 선택합니다. 참가자 ID는 익명 영문·숫자·`_`·`-` 1~32자로 입력합니다.
4. **Stimulus Validation**에서 모터 배열 동일성 분석을 실행합니다. **Training**에서 원형 응답과 자극을 연습하고, **Experiment A**에서 전체 108시행 흐름을 확인합니다.
5. A는 2~4초 준비 → 동시 자극 → 자극 종료 후 12초 응답 → 혼란도 1~7 → 저장입니다. 지도 클릭으로 마커를 최대 3개 추가하고, 거리를 고르거나 수정·삭제할 수 있습니다. 무응답 제출이 가능합니다. 블록 사이에는 휴식합니다.
6. **Experiment B**는 A에서 선정한 0°가 아닌 후보, 선정 규칙·근거, 첫 대응 제한시간과 정면 과제 사격 구역 반각을 먼저 입력해야 합니다. 두 조건 각 12이벤트가 초기 구성입니다. 마우스로 조준하고 왼쪽 버튼으로 사격합니다. 카메라 회전 중에도 한 이벤트의 스냅샷과 햅틱 정책은 바뀌지 않습니다.

`Escape`는 진동 중지·일시정지입니다. 진행 중인 자극은 기술 실패로 보존하며 정상 시행으로 채점하지 않습니다. `F9`는 일시정지 후 운영 화면을 엽니다. 개발 모드 외에는 이 화면에도 억제각 수치를 표시하지 않습니다. 연구자 설정과 시작 메뉴는 참가자를 착석시키기 전에 조작하세요.

Windows 실행 파일은 `GCCD_Project/Builds/Windows/GCCD.exe`입니다. **같은 폴더의 DLL과 `GCCD_Data`를 함께 옮겨야 합니다.** macOS 확인용 앱은 `GCCD_Project/Builds/macOS/GCCD.app`입니다. 빌드 여부와 실제 실행 검증 결과는 [검증 기록](docs/VALIDATION.md)을 확인하세요.

## X40 연결·교정

기존 bHaptics Player의 페어링과 연결 설정을 유지합니다. [장비 확인 절차](docs/HARDWARE_ACCEPTANCE.md)를 따르세요.

- 공식 SDK는 기존 로컬 Asset Store 캐시에서 가져왔으며 저장소 배포에서 제외합니다. 다른 PC에는 정식 **bHaptics Haptic Plugin (SDK2)**를 설치하세요. 임의 업그레이드가 필요하지 않습니다.
- **GCCD → bHaptics SDK2 → Check Official SDK and Add Prefab / Enable Compile-Time Adapter**로 공식 초기화 프리팹과 어댑터를 확인합니다. 기본 씬의 초기화 프리팹은 비활성 상태입니다. 개발 모드는 SDK를 초기화하거나 진동을 출력하지 않습니다.
- 공식 Developer Window에서 기존 앱을 연결·배포한 뒤 **Device Check → 공식 SDK 초기화 및 연결 확인**을 누릅니다. 키는 연구 설정·로그·Git에 저장하지 않습니다.
- 공식 [PlayMotors 문서](https://docs.bhaptics.com/sdk/unity/references/library)는 Vest의 32모터 배열을 명시합니다. 로컬 SDK 구현은 배열 길이를 네이티브 API에 전달하지만 이것만으로 X40 40채널 호환성을 증명하지 않습니다. 32모터 맵을 복사하거나 `PlaySingleMotor`를 X40 인덱스 테스트에 사용하지 않습니다.
- Calibration의 실제 장비 시험은 연구자가 명시적으로 허용해야 합니다. 단일 모터를 확인하고 40개 인덱스의 실제 방위각·보정값을 저장합니다. API의 40채널 처리와 물리 동시성을 별도로 확인합니다.
- 위협별 출력을 순차 호출하지 않습니다. 40채널 **최댓값 합성 배열 한 개**를 제출하며, 새 위협마다 이전 요청을 취소하지 않습니다. 정수 강도는 0~100, 양자화는 AwayFromZero입니다.

## 본 실험 설정

설정은 `Application.persistentDataPath/DtsSettings/experiment_config.json`에 저장합니다. 화면에 전체 경로가 표시됩니다. 파일도 직접 편집할 수 있습니다. 연구 설정에는 SDK 자격증명 필드를 넣지 않습니다.

방향 허용오차, L/H, 위치 보정, 지속시간, B 첫 대응 기준, 표본 수 근거, 최소 관심 효과, 동률 처리, 훈련 기준·재훈련 횟수·종료 규칙, 실패·제외 규칙과 주 분석 모형은 파일럿/사전등록 후 확정해야 합니다. 개발 모드의 미설정 방향 허용오차는 **임시 15°**로 동작하며 실제 연구의 확정값이 아닙니다.

MAIN은 장비·교정 확인, 사전 파일럿 기준과 실제 근거 파일의 SHA-256, 설정 잠금, 같은 참가자·같은 설정의 훈련 통과가 필요합니다. 파일럿의 최대 조건 쌍 동일 배열 비율을 넘는 자극은 자동 차단합니다. 파일럿 방향·거리 인지 성능 충족 여부는 연구자가 실제 자료로 판정하며 자동으로 만들어 주지 않습니다. 설정 변경 후에는 다시 잠그고 훈련합니다. B는 A와 독립된 참가자를 확인해야 하며 같은 ID의 반대 실험 MAIN 자료가 있으면 차단합니다. 다른 ID로 재참여한 실제 인물의 동일성은 연구자가 관리해야 합니다.

## 데이터와 재개

기본 경로: `Application.persistentDataPath/ExperimentData/<자료구분>/<A 또는 B>/<익명 ID>/<세션 ID>/`.
개발·파일럿·본 실험·훈련·교정·자극 검증 자료를 분리합니다.

- `session_metadata.json` / `.sha256`: 설정 스냅샷, Unity/SDK/매핑 버전, 시드, 실제 블록 순서와 설정 해시.
- `journal/*.started.json`: 출력 전에 내구성 있게 기록하는 원본 위협·정책·요청 배열.
- `journal/*.committed.json`: 정확한 JSON payload의 SHA-256을 포함하는 원자적 완료 기록.
- `runtime_events.csv`: 출력 요청 전/후, 응답 시작, 출력 중지, 게임 사격 기록.
- `trials.csv`, `threats.csv`, `haptic_outputs.csv`, `responses.csv`, `game_actions.csv`: 분석용 파생 테이블.
- `distance_confusion.csv`, `data_validation.csv`: 매칭 진단과 무결성 오류.

각 완료 기록이 원본이며 CSV는 재생성할 수 있습니다. 비정상 종료 후 **세션 재개**에 기존 폴더를 입력하면 완료 시행을 재출력하지 않습니다. 미완료 시행은 기술 실패로 확정하고 다음 시행부터 계속합니다. 자동 재시행이나 참가자 응답 보정은 하지 않습니다. Data Review는 체크섬을 확인하고 CSV를 재생성합니다.

```sh
./scripts/run-core-tests.sh
python3 scripts/analyze_session.py '/실제/세션/폴더'
```

분석기는 한 세션의 기술통계만 출력합니다. A의 분모는 억제 여부와 관계없이 원래 3개이며, B 성공률은 정상 출력 시행의 실패·시간 초과를 포함합니다. 성공 반응시간만으로 우월성을 결론 내리지 않습니다. 통계적 검정이나 후보 억제각 자동 선정은 확정된 분석계획 없이 실행하지 않습니다.
